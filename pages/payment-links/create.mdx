Cria um link de pagamento: um checkout que aceita vários pagamentos, de clientes diferentes. A API devolve a `url` para você compartilhar.

<Card horizontal>
  Requer a permissão `CHECKOUT:CREATE`.
</Card>

<Card title="Entenda o link de pagamento" icon="book-open" href="/pages/cobrar/link-de-pagamento" horizontal>
  A diferença para o checkout, o que o link não aceita e como acompanhar os pagamentos.
</Card>

O corpo é o mesmo de [Criar um Checkout](/pages/payment/create), sem `customerId` e sem `upSellProductId`. A rota já define o tipo: não mande `frequency`.

**Exemplo:**
```json
{
  "items": [
    { "id": "prod_abc123xyz", "quantity": 1 }
  ],
  "externalId": "link-campanha-123",
  "completionUrl": "https://seusite.com/obrigado",
  "methods": ["PIX", "CARD"]
}
```

**Exemplo com parcelamento no cartão:**
```json
{
  "items": [
    { "id": "prod_abc123xyz", "quantity": 1 }
  ],
  "methods": ["PIX", "CARD"],
  "card": { "maxInstallments": 6 }
}
```

## Erros

Além dos erros de [Criar um Checkout](/pages/payment/create#erros):

| Erro | Motivo |
|---|---|
| `You cannot pass a customer for a checkout with multiple payments frequency` | O link não aceita `customerId`: cada cliente preenche os próprios dados. |
| `Apple Pay and Google Pay are only available for one-time checkouts` | Apple Pay e Google Pay só valem no checkout. |
