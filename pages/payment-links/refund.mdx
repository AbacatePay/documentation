---
title: Reembolsar pagamento de link
openapi: 'POST /payment-links/refund'
---

Reembolsa o valor total de um pagamento feito num link de pagamento, por Pix ou cartão. O link continua ativo.

<Card horizontal>
  Requer a permissão `REFUND:CREATE`.
</Card>

<Card title="Entenda os reembolsos" icon="rotate-left" href="/pages/vender/reembolsos" horizontal>
  Regras, status, cartão já liquidado, webhooks e todas as mensagens de erro.
</Card>

O `id` é o do pagamento: a rota recusa o `bill_` do link. Cada pagamento do link é reembolsado separado, e o id dele aparece no dashboard, em **Sua Loja → Links de pagamento**, na lista de transações do link.

| Prefixo | O que é |
|---|---|
| `char_`, `pix_char_`, `card_` | Um pagamento do link. |

```json
{
  "id": "pix_char_abc123xyz",
  "reason": "Cobrança duplicada."
}
```

`reason` é opcional, com até 500 caracteres.

## Erros desta rota

| Mensagem em `error` | Quando acontece |
|---|---|
| `Use o publicId da cobrança individual (char_, pix_char_ ou card_), não do link de pagamento.` | O `id` é o `bill_` do link. |
| `Identificador inválido para esta rota. Use char_, pix_char_ ou card_.` | Prefixo de `id` não aceito. |
| `Use a rota /v2/checkouts/refund para reembolsar cobranças únicas.` | O pagamento é de um checkout. |
| `Use a rota /v2/transparents/refund para reembolsar cobranças transparentes.` | O `id` é de uma cobrança do checkout transparente. |
| `Cobranças de assinatura não podem ser reembolsadas pela API v2.` | O pagamento é de uma assinatura. |

As demais mensagens, como saldo insuficiente ou cobrança em disputa, estão em [Reembolsos](/pages/vender/reembolsos#mensagens-de-erro).
