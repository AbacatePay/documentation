---
title: Reembolsar pagamento de link
openapi: 'POST /payment-links/refund'
---

Reembolsa integralmente um pagamento realizado em um link de pagamento. O valor reembolsado é igual ao valor original da transação — não há reembolso parcial.

<Warning>
  Cobranças de assinatura (checkout `bill_...` ou pagamento de uma assinatura) não podem ser reembolsadas pela API v2. A API retorna `Cobranças de assinatura não podem ser reembolsadas pela API v2.`
</Warning>

<Card title="Obrigatório" horizontal>
  Apenas `id` é obrigatório: o ID da cobrança de um pagamento específico, não o `bill_...` do link.
</Card>

O campo `id` aceita:

| Prefixo | Recurso |
|---|---|
| `pix_char_...` | Pagamento do link feito via PIX |
| `card_...` | Pagamento do link feito no cartão |
| `char_...` | Cobrança (formato genérico) |

<Warning>
  O `bill_...` do link é recusado com `Use o publicId da cobrança individual (char_, pix_char_ ou card_), não do link de pagamento.`
</Warning>

<Note>
Reembolsos atuam sobre um **pagamento específico**, não sobre o link como um todo. Se o mesmo link recebeu vários pagamentos, cada um precisa ser reembolsado individualmente.

O ID de cada pagamento aparece no dashboard, em **Links de pagamento** → o link → transações. Por lá você também pode reembolsar direto.
</Note>

**Exemplo mínimo:**
```json
{
  "id": "pix_char_abc123xyz"
}
```

**Exemplo com motivo:**
```json
{
  "id": "pix_char_abc123xyz",
  "reason": "Cobrança duplicada."
}
```

**Resposta:**
```json
{
  "data": {
    "id": "tran_abc123xyz",
    "status": "COMPLETE",
    "amount": 10000,
    "reason": "Cobrança duplicada.",
    "originalId": "pix_char_abc123xyz",
    "createdAt": "2026-10-05T14:30:00.000Z"
  },
  "success": true,
  "error": null
}
```

`id` é a transação de reembolso, `originalId` repete o `id` enviado e `reason` vem `null` quando não é informado.

<Tip title="Idempotência" horizontal>
Uma nova chamada para um pagamento já reembolsado não cria outro reembolso: a API retorna o erro `Esta cobrança já foi reembolsada.` (HTTP 400). Trate esse erro como "já reembolsado".
</Tip>

---

## Regras de negócio

- **Reembolso total apenas** — o valor é sempre igual ao valor original da transação.
- **Métodos suportados** — `PIX`, `PIX_QRCODE` e `CARD`. Boleto, TED e movimentações internas não são reembolsáveis via API.
- **Estado exigido:**
  - `PIX` / `PIX_QRCODE` — transação precisa estar `COMPLETE`.
  - `CARD` — transação precisa estar `APPROVED` ou `COMPLETE`.
- **Disputas** — transações em disputa (`UNDER_DISPUTE` ou `metadata.underDispute=true`) não podem ser reembolsadas por este endpoint.
- **Saldo** — o valor é debitado do saldo `available` da loja (ou `pending`, em casos específicos de `CARD`). Sem saldo, retorna `INSUFFICIENT_FUNDS`.
- **Modo dev (sandbox)** — em `devMode` o reembolso é confirmado instantaneamente, sem chamar o provider real.
- **Status final após o reembolso:**
  - A transação original vira `REFUNDED`.
  - O billing daquele pagamento vira `REFUNDED`.
  - O payment intent vira `REFUNDED`.
  - É criada uma nova transação que representa o reembolso; o ID dela volta no campo `id` da resposta.

<Note>
Ao concluir, é disparado o webhook [`checkout.refunded`](/pages/webhooks/events/checkout). Configure seu endpoint em [Webhooks](/pages/webhooks/create) para receber a notificação.
</Note>

## Códigos de erro

| Código | Significado |
|---|---|
| `LOCK_NOT_ACQUIRED` | Outra operação está em andamento para esta loja — tente novamente em instantes. |
| `TRANSACTION_NOT_FOUND` | O `id` informado não existe ou não pertence à loja. |
| `TRANSACTION_NOT_REFUNDABLE` | A transação não está em um estado reembolsável (precisa estar `COMPLETE`, ou `APPROVED`/`COMPLETE` para `CARD`). |
| `TRANSACTION_UNDER_DISPUTE` | Transação em disputa — não pode ser reembolsada. |
| `INVALID_METHOD` | Apenas `PIX`, `PIX_QRCODE` e `CARD` podem ser reembolsados. |
| `INSUFFICIENT_FUNDS` | Saldo da loja menor que o valor da transação. |
| `STORE_NOT_FOUND` | Loja não encontrada. |
| `REFUND_REQUEST_FAILED` | Falha ao criar a transação no ledger ou ao acionar o provider. |
| `REFUND_CONFIRMATION_FAILED` | Falha ao confirmar o reembolso após a criação. |

**Exemplo de erro:**
```json
{
  "data": null,
  "success": false,
  "error": "INSUFFICIENT_FUNDS"
}
```

## Exemplo cURL

```bash
curl -X POST https://api.abacatepay.com/v2/payment-links/refund \
  -H "Authorization: Bearer $ABACATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "pix_char_abc123xyz",
    "reason": "Cobrança duplicada."
  }'
```
