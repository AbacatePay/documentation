## Base URL

```
https://api.abacatepay.com/v2
```

O ambiente (Modo Teste ou produção) vem da chave de API usada, não da URL.

## Autenticação

Toda requisição leva a chave de API no header `Authorization`:

```bash
Authorization: Bearer SUA_CHAVE
```

Veja como criar a chave e as permissões de cada rota em [Chaves de API e permissões](/pages/comecar/chaves-de-api).

## Formato de resposta

Todos os endpoints devolvem JSON com a mesma estrutura:

```json
{
  "data": { "id": "bill_abc123xyz" },
  "success": true,
  "error": null
}
```

Em caso de erro:

```json
{
  "data": null,
  "success": false,
  "error": "Mensagem descritiva do erro"
}
```

Os valores monetários são sempre inteiros em centavos: `1000` = R$ 10,00.

## Códigos de status HTTP

| Código | Quando acontece |
|--------|-----------------|
| `200` | Sucesso |
| `400` | A requisição está bem formada, mas uma regra de negócio a recusou. Também é a resposta quando o recurso não é encontrado (ex.: `Customer not found`). |
| `401` | Problema na chave de API: ausente, inválida, expirada, de outra versão ou sem a permissão da rota |
| `403` | Sessão de login da CLI tentando chamar uma rota que tira dinheiro da loja |
| `422` | O corpo ou a query não seguem o schema: campo obrigatório faltando, tipo errado ou valor fora do enum. A mensagem diz qual campo. |
| `429` | Limite de requisições atingido |
| `5xx` | Erro interno. Tente de novo com espera crescente. |

### Erros de autenticação

| `error` | Causa |
|---------|-------|
| `Unauthorized` | O header `Authorization` não foi enviado ou está fora do formato `Bearer SUA_CHAVE` |
| `Invalid or inactive API key` | A chave não existe ou foi excluída |
| `API key has expired` | A chave passou da data de validade |
| `IP address not whitelisted` | A chave só aceita alguns IPs, e a requisição veio de outro |
| `API key version mismatch` | Chave da v1 numa rota da v2, ou o contrário |
| `Insufficient permissions` | A chave não tem a permissão da rota. Crie uma chave nova com a permissão; não dá para editar as permissões de uma chave. |
| `Invalid API call` | A rota não existe. Confira o método e o caminho. |

## Limites

Cada loja pode fazer até **100 requisições por segundo**, somando todas as chaves do Modo Teste e de produção. Acima disso, a API responde `429 Too many requests`.

Toda resposta traz o uso do limite nos headers:

| Header | O que mostra |
|--------|--------------|
| `RateLimit-Limit` | O limite da janela (100) |
| `RateLimit-Remaining` | Quantas requisições ainda cabem na janela atual |
| `RateLimit-Reset` | Em quantos segundos a janela recomeça |

## Paginação e filtro por data

Os endpoints de listagem aceitam **paginação por cursor** e **filtro por data** de criação (`createdAt`).

### Paginação por cursor

As listas vêm dos itens mais recentes para os mais antigos.

| Param | Tipo | Descrição |
|-------|------|-----------|
| `limit` | `integer` | Itens por página (1–100, padrão `100`) |
| `after` | `string` | Cursor da próxima página: use o valor de `pagination.next` |
| `before` | `string` | Cursor da página anterior: use o valor de `pagination.before` |

As respostas de listagem trazem o objeto `pagination` junto do envelope:

```json
{
  "success": true,
  "data": [],
  "error": null,
  "pagination": {
    "hasMore": true,
    "next": "cust_abc123",
    "before": null
  }
}
```

| Campo | Descrição |
|-------|-----------|
| `next` | Cursor da próxima página. Vem `null` na última página. |
| `before` | Cursor da página anterior. Vem `null` na primeira página. |
| `hasMore` | `true` quando existe uma próxima página. |

Para avançar, passe `after` com o valor de `pagination.next`:

```bash
GET /v2/customers/list?limit=20&after=cust_abc123
```

### Filtro por data

| Param | Tipo | Descrição |
|-------|------|-----------|
| `startDate` | `string` | Data inicial, inclusive (`YYYY-MM-DD`) |
| `endDate` | `string` | Data final, inclusive (`YYYY-MM-DD`) |

Os dois são opcionais e podem ser usados sozinhos ou junto com `limit`, `after` e `before`. As datas valem no fuso **America/Sao_Paulo**: `startDate=2026-01-15` inclui registros a partir de 15/01/2026, 00:00, horário de Brasília. Nenhuma das duas pode ser anterior a `2024-01-01` nem mais de um ano no futuro.

```bash
GET /v2/customers/list?startDate=2026-01-01&endDate=2026-01-31&limit=50
```

Aceitam paginação e filtro por data: clientes, cupons, produtos, checkouts, links de pagamento, assinaturas, webhooks, saques, Pix enviados, cobranças transparentes e as demais rotas `*/list` da v2.

## Erros mais comuns

<AccordionGroup>
  <Accordion title="422 — a requisição é recusada antes de chegar à regra de negócio">
    Algum campo está fora do schema. A mensagem diz qual, por exemplo `Property 'data.customer.cellphone' is missing`. Confira os tipos: `amount` é sempre inteiro em centavos (`1000` = R$ 10,00), não decimal, e os IDs são strings.
  </Accordion>

  <Accordion title="400 — os campos estão certos, mas a API recusa">
    Uma regra de negócio barrou a requisição, ou o recurso não foi encontrado. A mensagem no campo `error` diz o motivo. Exemplo: mandar `dueDate` num checkout sem `BOLETO` em `methods` responde `dueDate requires BOLETO in methods`.
  </Accordion>

  <Accordion title="401 — tenho a chave, mas recebo Unauthorized">
    Veja a causa no campo `error` e na tabela de [erros de autenticação](#erros-de-autenticação). Confirme também que o header está exatamente como `Authorization: Bearer SUA_CHAVE`, com espaço depois de `Bearer` e sem aspas.
  </Accordion>

  <Accordion title="429 — Too many requests">
    A loja passou de 100 requisições por segundo. Espere o tempo de `RateLimit-Reset` e tente de novo.
  </Accordion>

  <Accordion title="5xx — erro do servidor">
    Erros `5xx` são temporários. Tente de novo com espera crescente (1 s, depois 2 s, depois 4 s). Se continuar por mais de alguns minutos, fale com o suporte em ajuda@abacatepay.com.
  </Accordion>
</AccordionGroup>
