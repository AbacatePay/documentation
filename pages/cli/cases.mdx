Cenários práticos usando a AbacatePay CLI.

---

### Teste rápido de integração local

Teste o fluxo de pagamento e o seu endpoint de webhook antes de ir para produção.

Antes, cadastre no dashboard, com o Modo Teste ligado, um webhook v2 assinando `transparent.completed` (qualquer URL HTTPS pública serve). Sem um webhook de dev mode cadastrado, o `listen` não recebe nada.

```bash
# 1. Autentique com uma conta em dev mode
abacatepay login

# 2. Inicie o listener
abacatepay listen --forward-to http://localhost:3000/webhooks/abacatepay

# 3. Em outro terminal, crie uma cobrança transparente pela API ou SDK
#    e simule o pagamento com o id retornado
abacatepay payments simulate pix_char_abc123xyz
```

O evento de pagamento aparece no `listen` e chega na sua aplicação com o header `X-Webhook-Signature`, como em produção.

---

### Debug de webhooks

Veja o payload de cada evento e o que sua aplicação respondeu.

```bash
# Mostra o JSON de cada evento recebido
abacatepay -v listen --forward-to http://localhost:3000/webhooks/abacatepay

# Encaminhamentos que sua aplicação recusou (status fora de 2xx), com o corpo da resposta
jq 'select(.msg=="webhook_forward_error") | {event, status_code, response_body}' ~/.abacatepay/logs/transactions.log
```

<Tip>
Se sua aplicação rejeita a assinatura, confira se você está calculando o HMAC sobre o corpo **raw** da requisição, antes de qualquer parse. Veja [Segurança de Webhooks](/pages/webhooks/security#2-assinatura-hmac).
</Tip>

### Automação em CI/CD

Em CI, use `--key` para autenticar sem navegador e confie no código de saída de cada comando.

```bash
set -e

# Autentica com a chave de dev mode guardada nos secrets do CI
abacatepay login --key "$ABACATEPAY_DEV_API_KEY"

# Cria a cobrança pela API (ex.: com o seu SDK ou curl) e simula o pagamento.
# Se a simulação falhar, o comando sai com código 1 e o job para aqui.
abacatepay payments simulate "$CHARGE_ID"
```

<Tip>
Não interprete o texto da CLI em scripts — ele é feito para leitura humana e pode mudar entre versões. Para conferir o status da cobrança depois da simulação, consulte a API em [Checar status](/pages/transparents/check).
</Tip>

### Múltiplas contas

Mantenha mais de uma conta salva com `--name`. O perfil ativo é sempre o do último login.

```bash
abacatepay login --name loja-a --key "chave_loja_a"
abacatepay login --name loja-b --key "chave_loja_b"

# Volta a usar a loja A
abacatepay login --name loja-a --key "chave_loja_a"
abacatepay listen --forward-to http://localhost:3000/webhooks/abacatepay
```
